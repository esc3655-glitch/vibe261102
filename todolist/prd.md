# PRD: 오늘의 할일 (Today's To-Do)

- 문서 버전: v0.1 (설계 초안)
- 작성일: 2026-11-02
- 상태: 설계 단계 (구현 전)

---

## 1. 개요

### 1.1 배경
할 일 관리 도구는 많지만 대부분 프로젝트·마감일·태그 등 기능이 많아 "오늘 무엇을 해야 하는가"에 집중하기 어렵다. **오늘의 할일**은 하루 단위의 할 일만 빠르게 적고, 체크하고, 돌아보는 데 집중한 가벼운 웹페이지다.

### 1.2 목표
- 3초 안에 할 일 하나를 추가할 수 있다.
- 오늘 해야 할 일과 진행 상황(완료율)을 한눈에 볼 수 있다.
- 별도 설치·회원가입 없이 브라우저에서 바로 사용한다.
- 새로고침하거나 브라우저를 다시 열어도 데이터가 유지된다.

### 1.3 비목표 (이번 범위에서 하지 않는 것)
- 회원가입/로그인, 서버 저장, 기기 간 동기화
- 프로젝트·카테고리 계층, 협업/공유
- 반복 일정, 알림(푸시), 캘린더 연동
- 네이티브 앱

## 2. 대상 사용자 및 시나리오

### 2.1 페르소나
| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| 직장인 | 출근 직후 오늘 할 일을 정리 | 빠른 입력, 우선순위 표시 |
| 학생 | 과제·공부 계획을 하루 단위로 관리 | 완료 체크의 성취감, 진행률 |
| 프리랜서 | 여러 잡무를 하루 안에 처리 | 미완료 항목을 다음 날로 넘기기 |

### 2.2 사용자 시나리오
1. 사용자가 아침에 페이지를 연다 → 오늘 날짜와 빈 목록(또는 어제 미완료 항목 안내)이 보인다.
2. 입력창에 "보고서 초안 작성"을 입력하고 Enter → 목록 맨 아래에 추가된다.
3. 중요한 항목에 우선순위 "높음"을 지정한다 → 목록 상단으로 정렬된다.
4. 작업을 끝내면 체크박스를 클릭 → 취소선과 함께 완료 처리되고 진행률이 갱신된다.
5. 다음 날 페이지를 열면 → "어제 못 끝낸 할 일 3개를 오늘로 가져올까요?" 안내가 뜬다.

## 6. 데이터 모델

### 6.1 Todo 객체
```ts
type Priority = 'high' | 'normal' | 'low';

interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~100자, 앞뒤 공백 제거
  done: boolean;
  priority: Priority;  // 기본값 'normal'
  date: string;        // 'YYYY-MM-DD' (로컬 기준, 이 할 일이 속한 날짜)
  createdAt: number;   // epoch ms
  completedAt?: number;
  memo?: string;       // P2
  order?: number;      // P2, 수동 정렬용
}
```

### 6.2 저장 구조 (localStorage)
| 키 | 값 | 설명 |
|---|---|---|
| `todayTodo:v1:todos` | `Todo[]` (JSON) | 전체 할 일 목록 |
| `todayTodo:v1:settings` | `{ theme: 'system'\|'light'\|'dark', filter: 'all'\|'active'\|'done' }` | 사용자 설정 |
| `todayTodo:v1:lastOpenedDate` | `'YYYY-MM-DD'` | 이월 배너 표시 판단용 |

- 키에 버전(`v1`)을 포함하여 향후 스키마 변경 시 마이그레이션 가능하게 한다.
- 파싱 실패 시 기존 데이터를 `todayTodo:v1:todos.corrupt`로 백업 후 빈 목록으로 시작.

## 7. 기술 설계

### 7.1 기술 스택
- **HTML + CSS + Vanilla JavaScript (ES Modules)** — 빌드 도구 없이 정적 파일로 배포
- 외부 의존성 없음 (선택: Pretendard 웹폰트)
- 배포: GitHub Pages / Netlify 등 정적 호스팅, 또는 로컬에서 `index.html` 직접 열기

> 선택 근거: 기능 규모가 작고 서버가 필요 없어 프레임워크 도입 비용이 이점보다 크다. 이후 기능이 커지면 React/Vite로 이전을 검토한다.

### 7.2 폴더 구조 (예정)
```
todolist/
├── prd.md            # 본 문서
├── index.html        # 마크업
├── css/
│   └── style.css     # 테마 변수, 레이아웃
└── js/
    ├── main.js       # 진입점, 이벤트 바인딩
    ├── store.js      # 상태 관리 + localStorage 입출력
    ├── todo.js       # Todo 생성/검증/정렬 로직 (순수 함수)
    ├── date.js       # 로컬 날짜 키 생성, 포맷
    └── render.js     # DOM 렌더링
```

### 7.3 아키텍처
단방향 데이터 흐름:

```
사용자 이벤트 → action(store.dispatch) → state 갱신 → localStorage 저장 → render(state)
```

- `store.js`: `getState()`, `dispatch(action)`, `subscribe(listener)` 제공
- 액션 종류: `ADD`, `TOGGLE`, `EDIT`, `DELETE`, `UNDO_DELETE`, `SET_PRIORITY`, `CLEAR_DONE`, `CARRY_OVER`, `SET_FILTER`, `SET_THEME`
- `todo.js`의 로직은 DOM에 의존하지 않는 순수 함수로 작성하여 단위 테스트 가능하게 한다.
- 렌더링은 목록 전체 재렌더링으로 시작(항목 수가 적음), 성능 문제 시 키 기반 부분 갱신으로 개선.

### 7.4 주요 로직 규칙
- **오늘 날짜 키**: `new Date()`의 로컬 연·월·일로 `YYYY-MM-DD` 생성 (UTC 변환 금지).
- **자정 경과**: 페이지가 열린 상태에서 날짜가 바뀌면(1분 간격 체크 또는 `visibilitychange` 시 확인) 화면을 새 날짜로 갱신하고 이월 배너 조건을 재평가.
- **이월(CARRY_OVER)**: 오늘 이전 날짜의 `done === false` 항목의 `date`를 오늘로 변경. 배너는 하루 한 번만 표시.
- **삭제 되돌리기**: 삭제된 항목과 원래 위치를 5초간 메모리에 보관.
